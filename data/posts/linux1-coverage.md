리눅스마스터 1급 노트는 14주 70일로 시작했습니다. 일차마다 분량은 충분해 보였고, 문제 수도 다른 트랙에 뒤지지 않았습니다. 그런데 노트가 시험 범위를 실제로 다 덮고 있는지는 따로 확인한 적이 없었습니다. 8월 초에 이것을 숫자로 확인해 보기로 했습니다.

## 진단 방법: 출제기준을 놓고 세어 보기

기준은 시험을 주관하는 KAIT 의 공식 출제기준입니다. 출제기준의 세부 항목을 하나씩 놓고, 그 항목을 대표하는 용어가 70일치 본문에 몇 번 나오는지 셌습니다. "다룬 것 같다"는 느낌 대신 출현 횟수를 보면, 이름만 스치고 지나간 항목과 아예 없는 항목이 바로 드러납니다.

결과는 이랬습니다.

| 항목 | 본문 출현 |
|---|---|
| PAM(인증 모듈) | 0회 |
| snort·fail2ban·tripwire(침입 탐지) | 0회 |
| sar(성능 분석) | 2회, 이름만 |
| LDAP(디렉터리 서비스) | 2회, 이름만 |
| KVM | 1회 |
| VirtualBox | 0회 |
| MySQL·MariaDB | 1회 |
| 사운드 장치 | 1회 |
| 스캐너·SANE | 0회 |

특히 가상화 관리는 3과목의 정식 항목인데 사실상 없었습니다. 과락 위험이 가장 큰 구멍이었습니다. 노트가 얇아서 생긴 문제가 아니라, 처음부터 범위에 빠져 있던 항목들이었습니다.

## 기존 일차에 흡수한 것

주제가 맞는 일차가 이미 있는 항목은 그 일차에 넣었습니다.

- **계정 관리(4주차 2일)**: PAM 을 모듈로 나눈 이유, `/etc/pam.d` 구조, 한 줄을 이루는 네 토막의 문법, 모듈 타입 네 가지와 제어 플래그 표, 자주 쓰는 모듈들. LDAP 은 DN·RDN 구조, 포트 389·636, LDIF, 이름 서비스 설정과 PAM 두 축을 함께 다뤘습니다. 분량은 19.5KB 에서 25KB 가 됐습니다.
- **접근 제어와 보안(11주차 4일)**: 네트워크 기반과 호스트 기반 침입 탐지의 비교표, fail2ban 의 설정 파일 구분, snort 의 세 가지 모드와 룰 헤더 분해, tripwire·AIDE 의 초기화→점검→갱신 순서. 16KB 에서 22KB 가 됐습니다.
- **프로세스(6주차 1일)**: sysstat 이 자료를 모으는 구조와 sar 의 주요 옵션, vmstat·iostat·mpstat·pidstat 이 각각 무엇에 답하는지, load average 읽는 법, CPU·I/O·메모리 병목을 가르는 판정표. 17.6KB 에서 24KB 가 됐습니다.

배포판마다 다른 부분은 숨기지 않고 적었습니다. 레드햇 계열과 데비안 계열의 PAM 설정 파일 이름, 보안 로그 위치, sar 자료가 쌓이는 경로가 서로 다르고, RHEL 7 과 8 사이에서 비밀번호 품질·잠금 모듈이 바뀐 점도 표시했습니다. 보강 뒤 다시 세어 보니 PAM 은 0회에서 6회, LDAP 은 2회에서 10회, fail2ban 은 0회에서 16회, snort 는 0회에서 11회, AIDE 는 0회에서 7회, sysstat 은 0회에서 11회가 됐습니다.

## 새 일차로 만든 것

가상화와 데이터베이스는 흡수할 자리가 없어 새 일차를 만들었습니다. 위치를 고민했습니다. 15주차를 뒤에 붙이면 "70일 마무리" 다음이라 시험 전에 못 보고 지나칠 수 있습니다. 그래서 주제상 제자리인 주차에 6일째로 넣었습니다.

- **7주차 6일, 가상화 관리**: 전가상화와 반가상화, 하이퍼바이저 1형·2형, 컨테이너와 가상 머신의 차이(커널 공유, namespace, cgroup), KVM 과 libvirt·virsh, Docker 이미지와 컨테이너, podman, VBoxManage.
- **9주차 6일, DB 서비스**: 설치와 기동, 초기 보안 설정, DDL·DML·DCL, 사용자와 권한, 설정 파일과 기본 포트, 덤프 백업과 복구, 접속 실패 진단.

이 일을 하려면 코드도 고쳐야 했습니다. 콘텐츠를 읽는 코드, 문제 색인을 만드는 스크립트, 동기화 스크립트 곳곳에 "한 주는 5일"이 숫자로 박혀 있었습니다. 이 제한을 걷어 내고, 콘텐츠를 바꾸지 않은 상태에서 문제 색인 결과가 이전과 똑같은지 먼저 확인했습니다. 트랙은 70일에서 72일이 됐습니다.

새 파일에는 되붙일 git 원본이 없어서 퀴즈를 보호하는 평소의 장치를 쓸 수 없었습니다. 대신 퀴즈 양식을 작업 지시에 명시하고, 만든 뒤 실제 화면 파서로 직접 읽어 두 파일의 7문항이 하나도 빠지지 않았는지, 보기가 넷씩인지, 해설이 빠진 문항이 없는지 확인했습니다.

## 장치 관리의 빈칸

같은 날 장치 관리 일차(7주차 4일)도 보강했습니다. 기존에는 프린터와 CUPS 만 있었고 출제기준에 있는 사운드와 스캐너가 빠져 있었습니다. ALSA 의 세 층 구조와 주요 명령, 예전 OSS 에서 ALSA 로 넘어온 흐름, 대화형 alsamixer 와 스크립트용 amixer 의 구분, SANE 의 백엔드·프런트엔드 구성과 진단 명령을 더했습니다. 기존 문장과 연습 문제는 건드리지 않고 81줄을 더하기만 했습니다.

## 남은 교훈

이 작업 뒤에 시작한 트랙은 집필 전에 출제기준이나 기출 분포부터 대조했습니다. 리눅스마스터 2급은 기출 문항을 세어 보고 커리큘럼 자체를 다시 나눴고, SQLD 는 공식 세부항목으로 주차를 짰습니다. 10월에는 1급 소개 문서에 70일로 남아 있던 표기를 실제 일수인 72일로 고쳤습니다. 숫자 하나도 실제와 어긋나면 노트 전체를 덜 믿게 되기 때문입니다.
