CertNote 에는 브라우저 안에서 도는 리눅스 셸이 있습니다. 설치도 가입도 없이 `ls -l`, `chmod`, `useradd` 같은 명령을 쳐 보고 결과를 바로 확인할 수 있습니다. 이 글은 그 셸이 내놓는 글자 하나하나를 실제 리눅스와 어떻게 맞췄는지에 대한 기록입니다.

## 왜 리눅스 셸이었나

학습 노트와 연습 문제만으로는 다른 무료 자료와 구별되는 점이 없었습니다. "읽은 내용을 손으로 쳐 볼 수 있어야 한다"는 결론을 내리고 먼저 경쟁 자료를 살폈습니다. 영어권에는 유료 강의 안에 CLI 시뮬레이터를 넣은 곳이 있었지만, 한국어 무료 사이트에서 브라우저 터미널 연습은 찾지 못했습니다. 리눅스마스터 무료 CBT 도 객관식뿐이었습니다.

시험 형식도 확인했습니다. KAIT 공식 안내에 따르면 리눅스마스터 1급 2차는 필기 40% 와 실기 60% 로 나뉘고, 실기는 작업식 5~7문항을 VirtualBox 위의 **Rocky Linux 8.8** 에서 풉니다. 2급은 사지선다지만 명령과 옵션의 결과를 묻는 문항이 많습니다. 그래서 기준 배포판을 시험 환경과 같은 Rocky Linux 8.8(GNU coreutils 8.30)로 고정했습니다.

## 저장한 답이 아니라 상태에서 계산한 출력

연습장은 명령마다 정해진 답을 꺼내 보여 주는 방식이 아닙니다. 가상 파일 시스템을 상태로 들고 있고, 명령이 그 상태를 바꾼 뒤 출력은 상태에서 계산합니다.

- 파일마다 inode 번호, 종류(파일·디렉터리·심볼릭 링크), 특수 비트를 포함한 권한, 소유자와 그룹, 크기, 수정 시각, 하드 링크 수를 가집니다.
- `/etc/passwd`, `/etc/group`, `/etc/shadow` 는 따로 저장하지 않고 계정 상태에서 그때그때 만들어 보여 줍니다. 파일과 실제 계정이 어긋날 일이 처음부터 없습니다.
- 일반 사용자로 바꾸면 권한 검사를 실제처럼 해서 `Permission denied` 가 납니다. 권한 단원에서 가장 중요한 경험이라 빼지 않았습니다.
- 같은 입력이면 언제나 같은 출력이 나옵니다.

## 골든 테스트: 같은 명령을 두 군데에 넣는다

출력 문구를 추측으로 쓰면 틀린 출력이 나오고, 틀린 출력은 오히려 신뢰를 깎습니다. 그래서 원칙을 하나 세웠습니다. **실제 Rocky 8.8 에서 찍은 출력과 비교하는 테스트 없이 명령을 추가하지 않는다.**

방법은 단순합니다. `rockylinux:8.8` 이미지에 기본으로 빠져 있는 `findutils` 와 `passwd` 만 더한 컨테이너를 만들고, 수집 스크립트가 시나리오 파일의 명령을 그 컨테이너에서 차례로 실행합니다. 시나리오마다 새 컨테이너를 띄우고, 한 시나리오 안의 명령은 같은 bash 하나에서 이어서 실행해 `cd` 와 `umask` 가 다음 명령에 남게 했습니다. 명령마다 표준 출력, 표준 오류, 종료 코드를 모두 기록하고, 시뮬레이터 테스트가 이 세 가지를 전부 비교합니다.

```
docker build -t certnote-rocky88 scripts/shell-lab
node scripts/shell-lab/golden.mjs
```

실제 셸과 모양을 맞추느라 신경 쓴 곳이 몇 군데 있습니다.

- 파일로 받은 `ls` 출력은 한 줄에 하나씩 나옵니다. 터미널에서 보는 여러 칸 배치와 다르므로 수집할 때 `-C` 와 80칸 너비를 줍니다.
- 스크립트 안에서 난 셸 오류는 `bash: line 3:` 처럼 시작합니다. 사람이 로그인 셸에서 보는 `-bash:` 모양으로 바꿔 비교합니다.
- 다른 사용자로 실행하는 단계는 컨테이너에서 `runuser -u` 로, 시뮬레이터에서는 세션을 하나 더 쌓아 실행합니다.
- 실행할 때마다 달라지는 값(시각, 장치 번호, inode 번호)은 양쪽을 같은 자리표시로 바꾼 뒤 비교합니다. 다만 `ls -li` 에서 "같은 번호끼리 같은지"는 유지해서, 하드 링크가 같은 inode 를 가리키는지는 그대로 검사합니다.

첫 공개 때 시나리오 9개, 319단계가 실제 출력과 모두 같았습니다. 지금은 시나리오 26개, 423단계입니다.

## 일부러 다르게 둔 것

모든 것을 실제와 똑같이 만들 수는 없어서, 다른 곳은 숨기지 않고 정해 두었습니다.

- `find` 와 `grep -r` 은 이름순으로 돕니다. 실제는 디스크 순서라 실행마다 달라질 수 있어 골든은 정렬해서 비교합니다.
- `ls -l` 권한 뒤에 붙는 SELinux 점은 없습니다. 컨테이너가 기준이기 때문입니다.
- 메시지는 C 로케일(영어)입니다. 시험 VM 의 언어 설정은 아직 확인하지 못했습니다.
- `vi`, `tar`, `systemctl` 처럼 실제로 있는 명령을 지원하지 않을 때는 `command not found` 로 속이지 않고 "아직 지원하지 않음" 안내를 띄웁니다. `tar` 는 계획표에 있었지만 아카이브 크기와 gzip 출력을 정확히 맞추기 어려워 뒤로 미뤘습니다.
- `ll` 별칭은 직접 넣었습니다. 실제 Rocky VM 에는 coreutils 설정 파일이 넣어 주지만, 골든을 찍은 최소 컨테이너에는 그 파일이 없습니다. 써 보다가 `ll` 을 쳤는데 동작하지 않아서 알게 된 차이입니다.

## 리뷰와 써 보기에서 잡힌 것

코드 리뷰에서는 `grep -R` 이 심볼릭 링크 고리를 만나면 탭이 멈추는 문제가 나왔습니다. 실제 grep 처럼 `recursive directory loop` 경고를 내고 건너뛰게 고쳤고, 그 동작도 실제 출력으로 골든에 더했습니다. 잘못된 와일드카드 `[z-a]` 에서 예외가 나던 것, 빈 변수가 빈 인자로 남던 것도 같은 방식으로 고쳤습니다.

직접 과제를 풀어 보다가 판정 문제도 찾았습니다. 권한 과제에서 `chmod -x` 를 먼저 한 뒤 기호 모드를 쓰면 결과가 664 가 되어 기대한 674 와 달라 통과하지 못했습니다. 정확한 숫자 대신 "기호 모드로 바꿨고, 소유자 실행 권한이 없고 그룹 쓰기 권한이 있는가"로 판정을 바꿨습니다. 휴대폰에서는 문제를 보면서 입력하기 어렵다는 점도 보였습니다. 그래서 화면이 좁으면 지금 단계의 문제를 터미널 바로 위에 붙이고, 키보드가 가린 만큼 터미널 높이를 줄여 입력 줄이 가려지지 않게 했습니다.

지금 연습장에는 권한, 하드·심볼릭 링크, 사용자와 그룹, 팀 공유 디렉터리(setgid·sticky), find, grep 과 파이프, 소유권까지 리눅스 과제 7개가 있습니다. 모두 출력이 실제 Rocky Linux 8.8 과 같은지 확인한 명령만으로 만들었습니다.
