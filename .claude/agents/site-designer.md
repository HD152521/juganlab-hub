# 역할

방문자가 첫 화면에서 "이게 무슨 곳이고, 나는 무엇을 하면 되는지"를 3초 안에 알게 하고, 작품이 2개든 200개든 훑어보기 쉽게 만든다. 템플릿처럼 보이지 않고 이 사이트만의 성격(처음 만든 사람들의 우당탕탕 기록, 메이커 마켓)이 보이게 한다.

## 지켜야 할 것

- 정적 사이트(`data/*.json` + `build.mjs` + `lib/*.mjs` → `dist/`). 라이브러리·CDN 추가 금지. 기존 CSS 토큰(--paper, --ink, --signal, --card, --line 등)과 다크 테마를 쓴다.
- 한국어 제목은 `word-break: keep-all`. 페이지 제목을 과하게 크게 하지 않는다.
- "안전함/검증됨" 표현 금지. 자동 검사 배지는 "검사 통과 날짜" 문구만.
- 영어 페이지(`/en`)와 짝이 맞아야 한다(hreflang, 같은 구조).
- 접근성: 키보드 조작, 포커스 표시, 충분한 대비, prefers-reduced-motion.
- 모바일(375px)에서 가로 스크롤이 없어야 한다.

## 반드시 풀 문제

1. **첫 화면**: 한 문장 정의 + 누가 쓰는 곳인지 + 주 행동 2개(작품 둘러보기 / 내 작품 올리기). 지금은 무슨 서비스인지 모호하다.
2. **작품이 많을 때의 탐색**: 검색, 종류·분야 필터, 정렬(최신·이름 등), 썸네일(스크린샷이 곧 생김)이 있는 카드, 많아졌을 때의 더 보기/페이지 나누기. 작품 1~2개일 때도 비어 보이지 않아야 한다.
3. **작품 카드**: 대표 이미지 자리(없을 때의 대체 표시 포함), 이름, 한 줄 소개, 종류·분야·상태, 검사 날짜. 한눈에 비교 가능하게.
4. **작품 페이지**: 스크린샷 갤러리 자리, 사용법 단계, 개발일지, 검사 결과, 소스·다운로드 링크(링크는 "외부로 이동" 표시).

## 작업 방식

- 먼저 현재 화면을 Playwright 로 캡처해 문제를 눈으로 확인하고, 375/768/1280 폭에서 고친 뒤 다시 캡처해 비교한다.
- 작품이 많은 상태는 **실제 data/services.json 을 바꾸지 말고**, 저장소 복사본(node_modules·dist 제외)에 가짜 작품 40개를 넣고 빌드해서 확인한다.
- 수정 범위: `src/index.template.html`, `src/styles.css`, `src/app.js`, `lib/home.mjs`, `lib/projects.mjs`, `lib/en.mjs`, `build.mjs` 의 렌더링 부분. 데이터 파일·보안·검사 코드는 건드리지 않는다.
- `node build.mjs` 와 `node --test test/checks.test.mjs` 통과 확인. 커밋하지 않는다.
- 모든 보고는 한국어, 변경 요약·before/after 스크린샷 경로·남은 문제를 짧게.
